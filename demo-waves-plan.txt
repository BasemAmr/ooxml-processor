### 2.1 Package `@ooxml/opc`
- **Package JSON entry**: `packages/opc/package.json` lines 10–15 (`exports: { ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" } }`).
- **Source entry point**: `packages/opc/src/index.ts` lines 1–117.
- **Documented limitations**:
  - Encrypted packages (`EncryptedPackage` OLE compound files) are deliberately rejected with `OpcEncryptedPackageError` (ADR 0002, `packages/opc/src/errors.ts` lines 212–234).
  - Decompression caps enforced mid-stream; archives exceeding ratio (`200:1`) or size budgets throw `OpcLimitError` (`packages/opc/src/limits.ts` lines 79–125).
  - External relationship targets (`TargetMode="External"`) are blocked from network dereferencing (SSRF boundary, `packages/opc/src/relationships.ts` lines 9–31).
  - Digital signatures stripped on save if package is modified (ADR 0011, `packages/opc/src/package.ts` lines 270–370).
- **Internal unexported modules (`[INDIRECT]`)**:
  - `packages/opc/src/testing/fake-xml.ts` (test-only, not for runtime use).
  - `packages/opc/src/testing/zip-fixtures.ts` (test-only archive builder).

### 4.12 Scope Decisions

| Cut / Downgraded Feature | Justification | User-Facing Effect in Demo |
| :--- | :--- | :--- |
| Cloud Share, Email, Move to Trash, Drive Shortcut | Browser-only client app without backend user storage accounts. | Rendered in File menu as disabled/greyed menu items with tooltip "(Requires Cloud Storage)". |
| Real-time Collaboration (OT / CRDT) | Monorepo is single-user v1 (`AGENTS.md`, ADR 0003, ADR 0013). | Single-user editing only; commands use stable structural IDs ready for future rebasing. |
| Live Word / LibreOffice automated diff | Tools absent in host environment (`F6`, ADR 0007). | Visual regression diff runner reports reference source as `previous-commit` and flags `UNVERIFIABLE-HERE`. |
| Full Chart / SmartArt vector rendering | `dml-chart` and `dml-diagram` deferred (`G3`, P9-20). | Rendered as styled, labelled placeholder boxes displaying title and diagram kind; round-trips losslessly. |
| Native Checkbox Content Control | `w14:checkbox` is outside ECMA-376 schema. | Treated as unknown SDT control; content rendered and preserved losslessly. |
| Data-bound SDTs live two-way sync | Custom XML part synchronization requires two-way XPath engine. | Data-bound SDTs display cached text and are marked read-only in UI. |
| Word 97–2003 `.doc` binary import | Out of scope; rejected as `OpcEncryptedPackageError` / CFB. | Alert banner: "Legacy binary .doc files are not supported. Please convert to .docx". |

### 5.3 Threading Model and Worker Boundary

Per **ADR 0005**, the v1 editor executes entirely on the **main thread**. Web workers are not used for layout in v1 because DOM APIs (`measureText`, font availability, `document.fonts`) and Canvas context metrics are main-thread bound.
However, to preserve the zero-rewrite worker migration path, the system enforces the following communication contract:
1. The **DisplayList** emitted by layout is 100% serializable (verified via `assertDisplayListSerializable` from `@ooxml/conformance`).
2. The payload transferred across the seam is a structured-cloneable snapshot:
   ```typescript
   export interface WorkerRenderPayload {
     readonly pageIndex: number;
     readonly displayList: DisplayList;
     readonly width: number;
     readonly height: number;
     readonly dpr: number;
   }
   ```
3. No closure, DOM node, or mutable AST reference crosses the render boundary.

### 5.6 UI Framework and RTL Strategy

- **UI Framework Decision**: **Vanilla TypeScript + HTML5 Canvas + Minimal DOM Component Shell**.
  - *Justification*: The repository uses strict ES2022, bundler resolution, and pinned dependencies (Rule R1, Invariant F1). Introducing React, Vue, or Svelte would add heavy transitive dependencies, duplicate DOM reconciliation over an already canvas-driven layout, and risk bloating `node_modules` on constrained storage.
  - Components are lightweight classes managing their own DOM tree (`HTMLElement`) with clean lifecycle methods (`render()`, `destroy()`).
- **Bidirectional UI & Document Strategy**:
  - The top-level application container (`#app-root`) supports switching `dir="ltr"` and `dir="rtl"`.
  - When in Arabic locale (`ar`), the entire menu bar, toolbar, sidebars, and dialogs flip horizontally, utilizing CSS Logical Properties (`margin-inline-start`, `inset-inline-start`, `border-inline-start`).
  - Document canvas rendering is independent of UI direction: document paragraphs render according to `w:pPr/w:bidi` and character-level UAX#9 resolving via `@ooxml/text`.

### 5.7 Error Handling, Limits, and Security

1. **Untrusted `.docx` Ingestion**:
   - All file uploads pass through `openPackage` with `DEFAULT_OPC_LIMITS` (512MB archive ceiling, 8,192 entries, 256MB per entry, 1GB uncompressed total, 200:1 ratio cap).
   - Decompression budget errors (`OpcLimitError`), malformed packages (`OpcPackageError`), and encrypted documents (`OpcEncryptedPackageError`) display non-crashing alert banners.
2. **SSRF Boundary**:
   - External relationship targets (`TargetMode="External"`) are never fetched automatically by the canvas engine. User-initiated link navigation displays a confirmation modal showing the target domain.
3. **Clipboard XSS Prevention**:
   - Pasted HTML is scrubbed using `sanitizeHtml` from `@ooxml/editor` to strip `<script>`, `<iframe>`, `on*` event handlers, and `javascript:` URIs before conversion to document commands.

### 6.1 Wave Rules and Execution Ordering

- **Dependency Rule**: Execution proceeds strictly in 13 vertical slice waves: $W0 \rightarrow W1 \rightarrow W2 \rightarrow \dots \rightarrow W12$.
- **Parallel vs Series Rule**:

| **2** | **DocumentModel Interface Missing Concrete Class** (`editor.DocumentModel` is an abstract interface without a default implementation in `@ooxml/wml`). | W2, W7 | Compilation error in editor commands (`Type 'CT_Document' does not satisfy DocumentModel`). | Author `WmlDocumentModel` adapter inside `apps/demo/src/adapters/document-model.ts`, adapting `CandidateCMutableTree` spike logic from ADR 0003. |
| **3** | **Footnote / Body Area Pagination Cycle Oscillation** (Footnote pushes reference to next page, oscillating infinitely). | W4 | Pagination loop exceeding iterations or hanging during page reflow. | Utilize `paginateWithFootnotes()` from `@ooxml/layout` with `fixpoint()` driver; automatically selects the larger reserve on oscillation per ADR 0016. |
| **4** | **Bidi Boundary Caret Ambiguity & Teleporting** (Single logical position maps to two distinct screen coordinates at LTR/RTL Seam). | W6 | Caret renders on the wrong visual side of text or jumps erratically during arrow navigation. | Adhere strictly to ADR 0014 and `@ooxml/editor`'s `caretRect` and `Affinity` model; never derive caret coordinate from pure character offset. |
| **5** | **InputProxy Blur / Focus Trap on Virtual Keyboards** (Hidden textarea loses focus during canvas touch interaction, dropping keystrokes). | W7 | Virtual keyboard closes on mobile or typing stops responding after mouse click. | Bind canvas mousedown to `proxy.focus({ preventScroll: true })`; maintain proxy coordinates at `caretRect` without `display: none`. |
| **6** | **Clipboard Style Conflict Restyling** (Pasted fragment styles with conflicting definitions silently altering existing paragraphs). | W7 | Entire destination document changes font or styling after a paste operation. | Enforce ADR 0015 default `mergeFormatting` in `deserializeClipboard`; rename conflicting style IDs under `keepSource`. |
| **7** | **DisplayList Serialization Failure** (Accidental leakage of closure, DOM node, or mutable AST reference into DisplayList). | W5, W12 | `structuredClone()` throwing `DataCloneError` in tests. | Continuous CI assertion using `assertDisplayListSerializable()` from `@ooxml/conformance`; enforce numeric primitive item types only. |
| **8** | **HarfBuzz WASM Loading Stalling Initial Layout** (Waiting for asynchronous WASM instantiation blocking first document paint). | W3 | Blank screen on initial load while HarfBuzz WASM compiles. | Default to `FallbackTextShaper` immediately for initial paint; hot-swap to HarfBuzz upon WASM resolution and relayout dirty paragraphs incrementally. |
| **9** | **Font Loading FOUT Layout Shift** (Asynchronous web fonts loading causing full document reflow and jumping scroll position). | W3, W4 | Visual layout flash and shifting line breaks across all pages when font loads. | Utilize `FontLoader.trackParagraphFont()` from `@ooxml/text`; invalidate only the specific paragraphs referencing the settled font via `P6-13` incremental relayout. |
